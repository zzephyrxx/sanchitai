## 二、P0（必须修）——本轮唯一根因

**P0-1 Dexie 写路径混入 Vue reactive proxy → `DataCloneError`，且失败静默**
- 现象：`Failed to execute 'put' on 'IDBObjectStore': #<Object> could not be cloned`（错误只进 console，界面无 toast、无失败反馈）。
- 影响面（实测全部复现）：**A3 排期写入**（`draftToEvent` 的 `agenda: draft.agenda` 为 genDrafts ref 深reactive 代理数组）、**A13 流转**（timeline 浅拷贝含 proxy）、**A14 材料循环**（`toggleMaterial` 对未变更材料 `return m` 原样返回 proxy）、**A17 谈话录入**（`member_ids: addForm.member_ids` proxy 数组）。
- 位置：`src/store/modules/work-data/index.ts`（addEvent/advanceStage/updateDevStage 调用方）、`src/utils/schedule-gen.ts`（draftToEvent）、`src/views/development/modules/dev-detail.vue`（toggleMaterial）、`src/views/talks/index.vue`（handleAdd）。
- 修改建议（一处根治 + 一处兜底）：
  1. 统一写通道深拷贝：在 store 的所有 `db.*.put/update/bulkPut` 前对入参做 `structuredClone(toRaw(x))` 或 `JSON.parse(JSON.stringify(x))`（本库数据皆可 JSON 化），或让 `useDexieLive` 出口统一返回 `toRaw` 深拷贝数据，从源头避免 proxy 入库；
  2. 兜底：所有写操作 `.catch(err => window.$message?.error('保存失败：' + err.message))`——当前 4 个功能失败时用户完全无感知，属体验缺陷叠加。
- 修复后必须复测：A3 写入+台历呈现、A10 幂等、A13 流转（类型/泳道/座位徽标/党费名单联动）、A14 材料循环、A17 录入后覆盖表变绿。
