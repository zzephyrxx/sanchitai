# 三尺台 v1 用户需求书

- 版本：v1.0（2026-11-18）
- 作者：用户代表（研究生党支部书记视角）
- 依据：对真实党支部工作资料目录（约 5.6GB，2024秋—2026秋 五个学期 + 支部建设 26-27 年规划 + 发展/党费/积分/五星考核等制度文件）的只读调研；调研中所有人员一律编号或化名，未复制任何含个人隐私的原文。
- 定位：三尺台是高校学工**个人离线工作台**。v1 只服务一种身份——研究生党支部书记；主视图是「台历」。

## 1. 用户画像

### 1.1 主用户：研究生党支部书记（兼职党务的博士生/硕士生）

| 维度 | 真实情况（来自调研） |
| --- | --- |
| 身份 | 全日制研究生，科研任务与本职党务并行；支部为"硕博一体化"纵向支部，覆盖博士与各年级硕士 |
| 支部规模 | 在库党员约 30-40 人（含预备），另有积极分子/发展对象/申请人约 10-20 人流动 |
| 支委班子 | 书记、副书记、组织委员、宣传委员四人分工，均由研究生兼任；支委换届约每年一次（"三上三下"程序） |
| 上线对接 | 学院党委 + 学院副书记（列席支部会议）；学院每月/每两周一次"学生党支部书记例会"传达部署 |
| 设备与环境 | 个人 Mac/Windows + 多设备同步盘（现场出现同步冲突文件）；学院另有线上"党建平台"做对外展示，内部管理仍靠本地文件 |
| 时间特征 | 白天科研、晚上与周末做党务；会议集中在工作日中午/下午；12 月、1 月、5-6 月是材料高峰 |

### 1.2 次要相关人（v1 不做账号，只在数据中体现）

- **副书记/组织委员/宣传委员**：分摊部分任务（帮扶排期、材料收审、新闻稿），v1 中仅作为事件的"主责人/协助人"字段。
- **学院党委**：下发通知、审批请示与批复，是"截止日期"的来源方。
- **党员/积极分子**：被记录方（到会情况、缴费、发展阶段），不是操作者。

### 1.3 核心诉求一句话

> "我要在一处看到：这周必须开什么会、交什么材料、谁到了期、谁没交党费——不用再翻五六个 Excel 和三层深的文件夹。"

## 2. 真实工作流叙事（调研还原）

### 2.1 一天（工作日晚，21:00-23:00）

白天实验做完，晚上打开电脑处理党务：学院群里来了两条通知（明天的书记例会改期、本周五前交"党员信息统计表"）。先改台历上的例会时间，再打开党员名册把新转入的 1 名博士党员补录进去（编号、年级、导师、入党时间）。9 月主题党日下周要开，从材料库里调出上次的活动方案模板，改主题、改流程，生成一份新策划书。合上电脑前看一眼本周日历：周三支委会、周五党课，没有遗漏才安心。

### 2.2 一周

- **固定动作**：随组会开展"组会前五分钟·科学家精神微讲堂"（每周，轮值党员主讲，拍照留档）；周末整理本周会议记录、签到表，把纸质三会一课记录本誊写补录（调研中真实存在"11.5 三会一课记录本誊写"待办）。
- **事件驱动**：学院书记例会（每月）后回来"传达部署"，例会上的新任务要拆进自己的月安排；某党员组织关系转入，当天要建档。
- **节奏约束**：线下会议每月不超过 3 次（转正、接收预备党员等"到期必须开"的会议除外）——排期时要合并（党课可并入党员大会、主题党日可并入专题学习）。

### 2.3 一学期（以秋季学期为例）

| 月份 | 固定事项 | 事件性事项 |
| --- | --- | --- |
| 9月（开局） | 支委会①；学院书记例会；本月主题党日；党费收缴启动 | 新生党员档案核查与组织关系接收；党员信息统计更新（学院要表）；九一八等纪念日主题党日 |
| 10月 | 支委会②；党员大会暨党课（第一季度，常合并换届/宣讲/专题学习） | 支委换届"三上三下"；新生档案收尾；结对帮扶排期 |
| 11月 | 支委会③；主题党日；积极分子校级党课（第 83 期）跟进 | 发展对象材料启动：征求意见、支委会确定、公示、备案；党员基本培训大课 |
| 12月 | 支委会④；本月主题党日；**谈心谈话集中月** | **接收预备党员大会、预备党员转正大会**（按预备期满日单开）；政审函调；书记抓党建述职；学期末书面报告 |
| 1月（收口） | 支委会⑤（期末总结）；**组织生活会暨民主评议党员**；党员大会暨党课（第二期：学期总结、积分通报） | 寒假线上学习布置；任务对照计划逐项销号 |
| 2-3月（春季开局） | 春季支委会①；组织生活会（部分年度放在春季学期初开） | 两会精神学习等主题党日 |
| 4月 | 支委会②；主题党日（劳模精神、专题培训类） | "两优一先"推荐启动 |
| 5月 | 支委会③ | **发展对象考核四件套**：集中考试（5.20）、志愿时长核验、谈心谈话、个人答辩（5.18）→ 支委会确定拟发展对象（5.21） |
| 6月 | 支委会④；党员大会（第三期） | **接收预备党员大会、转正大会**（6.19、6.25、6.26 连开）；**毕业生组织关系转接、档案移交**；七一活动 |
| 7月 | 学期总结 | 转正批复收尾（7.10）；暑期实践布置 |

### 2.4 一学年节点总览

9 月开局建档 → 10 月换届/首次大会 → 11 月发展启动 → 12 月接收转正+谈心谈话+述职 → 1 月评议收口 → 3 月春季启动 → 4 月活动密集 → 5 月发展对象考核 → 6 月接收/转正/毕业转接 → 7 月总结。**党员发展的"秋季链"与"春季链"平行存在，学院每年初下发时间节点表并注明"每学期初根据实际情况进行调整"。**

## 3. 调研发现：现状工具与痛点

**现状做法**（全部来自真实资料）：
- 任务组织 = 文件夹树（学期 → 月份 → "日期.事项"文件夹），计划性事项用"TODO 前缀文件夹"标记；
- 台账 = 一堆散装 Excel：党员信息（含学号/身份证/电话/宿舍等 22+ 字段）、党费逐月打勾表（0.2 元/月，"/"表示未在校）、按活动打列的签到表（到会/请假/未到会 + 到会率公式）、志愿时长表、积极分子活动登记表；
- 发展流程 = 学院版《党员发展、转正进度安排》总表（5 阶段 27 项材料）+ **每人**一个"发展材料"文件夹（1-5 阶段）+ 每人一份时间线 Excel；材料按编号体系（1、2.1、5.1、13.2、17.2、26、27.2…）对应档案袋；
- 活动档案链 = 策划书 → 主持词 → PPT → 会议记录 → 新闻稿 → 照片 → 平台发布 → 学期活动汇总表；
- 制度文件 = 积分管理（基础 60 + 履职 40 − 减扣 + 附加；申报→评定→公示→备案）、五星党员考核（五维赋星：政治 30/专业 30/实践 20/志愿 20/先锋，三星合格、四星优秀、五星标兵）、民主评议（优秀≤1/3）。

**痛点**（v1 要解决的）：
1. 同一事实散落多表：某人"是否到会"在签到表，"缴费"在党费表，"阶段"在时间线表，互不关联，改一处要改三处。
2. 每月手工做表：党费逐月复制打勾、到会率手算、月安排表手写 docx。
3. 截止日期靠脑子+文件夹前缀（TODO），漏一项就是漏一份学院要的材料。
4. 隐私集中暴露：身份证号、电话、宿舍号全在一张总表里，文件随手同步到网盘/群。
5. 纸质记录本要"誊写"进电子档，二次劳动。

## 4. v1 七大功能需求

> 通用约定：所有数据仅存本地（SQLite/JSON 均可），无网络依赖；党建红 #A81C24 仅用于关键强调（今日事项、到期预警、党旗等关键元素）；界面简约为先，单屏一个重点。

### 4.1 台历（主视图）

**用户故事**
- 作为书记，我想在打开应用 3 秒内看到"本周/本月要开什么会、交什么材料、谁到期"，以便不漏任何学院要求的节点。
- 作为书记，我想点一下任意一天就能加事项（如"周三 14:00-16:00 支委会，教六 1115"），以便 10 秒完成排期。
- 作为书记，我想让"三会一课"按规则自动铺满学期（支委会每月 1 次、党员大会每季度 1 次、党课每季度 1 次、主题党日每月 1 次），以便学期初一次性排好再微调。

**关键操作路径**
1. 打开应用 → 默认周视图（月视图一键切换）；今日列高亮。
2. 日历空白处单击/双击 → 新建事项弹层：标题、日期时间、结束时间、地点、类别、主责人、协助人、议程要点、关联模板。
3. "学期一键排课"：选学期起止 → 按三会一课规则生成草稿事项（可整批删除/逐个拖拽调整）。
4. 到期预警：材料/请示类事项在到期前 3 天于台历上变红点；当日事项在顶部"今日"条显示。

**数据字段建议**：`id, title, date, start_time, end_time, location, category(组织生活/党务常规/发展党员/品牌活动/服务实践/工作例会/理论学习), owner, helper, agenda(要点), recurrence(规则), status(计划/已完成/已取消), related_ids(关联人员/会议记录)`。

**期望交互**：类别用固定色标（红仅给组织生活与预警）；拖拽改期；周视图按"上午/下午/晚上"三段分栏，贴合学生作息；月视图在格内只显示"时间+标题"，点开看详情。

### 4.2 身份切换

**用户故事**
- 作为用户，我可能有"党支部书记/班长/社团负责人/辅导员"多重身份且互不打通，我想在顶部一键切换身份，以便当前界面只出现本身份的功能与数据。

**关键操作路径**
1. 侧栏底部"当前身份：党支部书记"点击 → 身份列表（首次使用引导创建）。
2. 切换后：台历、人员、台账、模板全部指向该身份数据库；无跨库搜索。
3. v1 仅实现"党支部书记"一个身份的真实功能，其余身份显示"规划中"占位。

**数据字段建议**：`identity { id, name(党支部书记/班长/…), color, created_at, db_scope }`；数据按 identity 分库或分 schema。

**期望交互**：切换不超过 2 步；当前身份常显（防止录入错库）；不做多身份数据合并/打通（产品铁律）。

### 4.3 人员可视化（座位/工位图）

**用户故事**
- 作为书记，我想在一张"实验室工位/教室座位"图上看到人头图标+姓名+身份色，点击人员看完整档案，以便认人、找人、快速掌握"谁在哪个组"。
- 作为书记，我想拖一个头像到新位置，以便新学期换工位后 1 分钟更新图。

**关键操作路径**
1. 人员页 → 两个标签："列表"与"座位图"；座位图支持多张图（如"理工大厦工位区""会议室固定座"）。
2. 座位图编辑模式：添加桌子/格子 → 拖人员头像入座；查看模式：点击头像弹出人员卡片（阶段、缴费状态、到会率三行摘要 + "查看详情"）。
3. 人员列表支持按类型（正式/预备/发展对象/积极分子/申请人）、按年级筛选；新增人员表单 ≤ 8 个必填字段。

**数据字段建议**：`member { id, code(编号), name(化名), type, group(研究方向组), grade, major, advisor, join_date(入党), full_date(转正), seat { map_id, x, y }, phone_opt(可选，默认不填), note }`。**v1 默认不收集身份证号**；手机号设为可选字段并在界面上打"敏感"标识。

**期望交互**：人头图标颜色 = 成员类型（正式=党建红、预备=红 50%、发展对象=橙、积极分子=蓝、申请人=灰）；欠缴党费/到期未谈话的成员在座位图上有角标；放大缩小流畅；人员总数 ≤ 80 时性能无忧。

### 4.4 三会一课排期

**用户故事**
- 作为书记，我想让系统按《支部工作条例》默认频次（支委会每月 1 次、党员大会每季度 1 次、党小组会按需、党课每季度 1 次、主题党日每月 1 次、组织生活会每年 1 次）生成本学期排期，并支持"党课并入党员大会"这类合并，以便既合规又不超"线下会议每月≤3 次"的负荷。
- 作为书记，我想给每次会议挂议程模板与记录模板，会后一键生成会议纪要初稿，以便少誊写。

**关键操作路径**
1. 三会一课页 → 学期视图（一眼看到本学期已排/缺排的会议类型）。
2. "按规范生成排期"→ 预览列表（每条可改日期/地点）→ 确认写入台历。
3. 会议详情：议程（环节+时间+内容）、参会人勾选 → 会后点"记录"→ 套用会议纪要模板 → 生成文档存材料库。
4. 系统对"当月线下会议超 3 次"给黄色提示（转正/接收大会除外）。

**数据字段建议**：`meeting { id, kind(支委会/党员大会/党小组会/党课/主题党日/组织生活会), date, time, location, agenda[], attendees[{member_id, status(到会/请假/未到会)}], attendance_rate, record_doc_id, merged_into(可空) }`。

**期望交互**：缺排检测用红/黄提示条（如"12 月尚未排主题党日"）；到会率自动计算，替代手工 Excel 公式；记录模板一键导出 docx/md。

### 4.5 党员发展台账

**用户故事**
- 作为书记，我想让每位"申请人→积极分子→发展对象→预备党员→正式党员"五阶段人员各有一张时间线，自动对照学院进度表（春秋两条链）标出"下一步该办什么、哪天到期"，以便 27 项材料一个不漏。
- 作为书记，我想点"下一节点"就看到该节点要哪些材料（编号体系）与模板，办理完打勾落日期，以便材料与档案袋一一对应。

**关键操作路径**
1. 发展台账页 → 左侧阶段泳道（申请人/积极分子/发展对象/预备/正式），人员卡片可跨泳道流转。
2. 点人员 → 个人时间线（节点列表：节点名、计划日期、实际日期、材料清单、状态）。
3. "下一步"卡片置顶显示：如"13.1 拟接收预备党员审查会议记录（12.10-15 窗口）"，附材料模板与填写要点。
4. 学院节点表更新时（每年初调整），支持导入/编辑本支部的时间窗参数。

**数据字段建议**：`dev_stage { member_id, stage(申请人/入党积极分子/发展对象/预备党员/正式党员), stage_date, next_node(节点编号+名称), next_due(预计日期), materials[{no, name, status(未开始/进行中/已归档), date}], timeline[{node, date, note}] }`；节点库内置 27 项标准材料编号与春秋季参考时间窗。

**期望交互**：泳道卡片显示"姓名+进入本阶段天数"；临近窗口期（±7 天）高亮；转正到期（预备期满一年）在台历自动生成"转正大会（固定时间会议）"候选事项。

### 4.6 党费台账

**用户故事**
- 作为书记，我想每月一次"批量记一笔"：本月应缴名单一键生成（0.2 元/学生月标准），逐人打勾确认，未缴的标红，以便 10 分钟完成当月党费并随时应付学院催表。
- 作为书记，我想看到任意人"近 6 个月缴费序列 + 欠缴月"，以便谈心谈话时提一句、积分评定时有依据。

**关键操作路径**
1. 党费页 → 当前收缴月 → "生成本月名单"（按在校状态过滤，新入党者从入党月起算）。
2. 逐人点"已缴/欠缴/减免"，支持备注（如"出差补缴"）。
3. 月末"汇总"：本月在缴/未缴人数、金额合计；一键导出学院格式报表（逐月矩阵）。
4. 欠缴人员联动：座位图角标 + 台历月末提醒"党费收尾"。

**数据字段建议**：`fee { member_id, year_month, amount(0.2), status(已缴/欠缴/减免/未在校), paid_date, note }` + `fee_month_summary { year_month, due, paid, unpaid }`。标准可配置（默认 0.2 元/月，正式与预备一致）。

**期望交互**：主视图是"人员×月份"矩阵（沿用真实做法），格子=0.2 或"/"或空；连续 2 月欠缴自动红色；导出格式对齐学院习惯（首列序号+姓名，月份列，合计列）。

### 4.7 谈心谈话 + 材料库

**用户故事（谈心谈话）**
- 作为书记，我想维护"谈话覆盖表"：谁今年谈过、上次何时、下次该谈谁（支委之间/支委与党员每年≥1 次；12 月集中谈），以便年终检查全覆盖时有据可查。
- 作为书记，我想 3 步录一条谈话记录（选人→选类型→写要点），并导出"谈心谈话记录表"，以便留痕归档。

**用户故事（材料库）**
- 作为书记，我想把常用公文模板（支委会纪要、党员大会议程、主题党日方案、请示、总结、谈话记录表）存一处，新建文档时选模板即得初稿，以便不再翻旧文件夹找"参考上一份"。
- 作为书记，我想把每次活动的产物（策划、纪要、新闻稿、照片）挂在对应台历事件下，以便活动"策划-执行-归档"一条链完成。

**关键操作路径**
1. 谈心谈话页：覆盖矩阵（成员×年度/学期）→ 未覆盖标黄；"新建谈话"向导：对象（可多人）→ 类型（日常/思想动态/发展节点/转正征求意见）→ 时间地点 → 要点 + 后续跟进 → 保存即入档并更新覆盖表。
2. 材料库：模板区（官方通用格式，用户自建/复制）+ 归档区（按事件或按人聚合）；"从模板新建"→ 填空（自动带出支部名、日期、人员名）→ 导出。
3. 台历事件详情页提供"附件区"：上传/链接本事件的策划与记录。

**数据字段建议**：`talk { id, date, location, type, member_ids[], content要点, follow_up, recorder }`；`doc_template { id, name, category(会议/活动/发展/财务/总结), body(带占位符), placeholders[] }`；`doc { id, template_id, event_id?, member_id?, title, body, created_at }`。

**期望交互**：覆盖表是唯一入口级视图（一屏看清缺口）；模板占位符 `{{姓名}}` `{{日期}}` 式替换；导出格式为 docx/Markdown 双支持。

## 5. 体验底线

1. **信息密度**：台历周视图默认显示全部 7 天×3 时段，不折叠重要事项；任何列表页不出现横向滚动超过 1 屏的关键字段。
2. **单屏重点**：每个页面只有 1 个主对象（台历页=本周，人员页=座位图，发展页=泳道，党费页=当月矩阵，谈话页=覆盖矩阵）；次级信息收进详情。
3. **高频操作 ≤ 2 步**：加事项、记到会、记缴费、录谈话、人员入座——从常驻界面出发均不超过 2 次点击（调研显示这些动作每周 3-10 次）。
4. **离线可靠**：无网全功能可用；数据本地存储；提供"一键备份为压缩包 + 从备份恢复"（用户有真实多设备同步冲突教训）；应用崩溃/强退不丢已确认写入的数据。
5. **数据安全**：v1 默认不录身份证号；电话为可选且带敏感标识；导出报表默认隐藏敏感列；应用层不联网、不上报任何数据；提供"整体加密库（可选口令）"。
6. **中式排版**：默认字体适配中文；党建红 #A81C24 仅用于关键强调（不超过界面用色 10%）。

## 7. v1 明确不做（非目标）

- 多人协同/云端同步/消息推送（数据纯本地）；
- 学院审批流线上化（请示批复仍是线下文件，v1 只做模板与台账）；
- 积分制/五星考核的自动计分（v1 可在人员档案中留展示位，计算放后续版本）；
- 班长/社团/辅导员身份的真实功能（仅占位）；
- 对外平台发布（新闻稿导出后由学院现有平台处理）。
